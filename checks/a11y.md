# Accessibility

`tools/a11y.mjs` serves a built folder, opens every page in headless Chrome at 320px and 1280px, and runs axe-core 4.14 with the WCAG 2.2 A and AA rules and heading order. At 320px it also measures sideways scroll (A11Y-008). Each axe rule maps to an A11Y rule in `brand/system/accessibility.md`; the rest fall under A11Y-001.

## How it runs

- In the brand repo, its own workflow, Accessibility, checks the built playbook when templates, styles, tokens or the playbook change.
- On the site, `tools/checks-site.mjs` checks the built pages. Requests to the site’s own address are answered from the build, so it checks the pull request, not the live site.
- It uses the installed Chrome through `playwright-core`, which downloads no browser. With no Chrome, it reports ‘not checked’.
- Fonts and unpkg load. Analytics, reCAPTCHA, comments and every other outside request are blocked, so a run sends nothing to them and gives the same result each time.

## Levels

axe’s ‘serious’ and ‘critical’ findings are proposed to block at launch, ‘moderate’ and ‘minor’ to warn (O-20). Until launch every finding warns (D-054).

## What it leaves out

- Sideways scroll on print and social frames, which are fixed sizes.
- `admin/` and `assets/`.
- Keyboard use, focus order, motion and reading at real distance (A11Y-007, A11Y-009): reviewer.
